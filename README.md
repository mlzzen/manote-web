# 麻记 Manote · Web 版

把 [manote](../manote)（Android / Kotlin + Jetpack Compose）搬到浏览器里的版本：**记录麻将局打完后的最终净输赢**，并在 PC 页面上把数据摊开来看。

界面语言：中文为默认，英文随浏览器语言自动切换，侧栏可手动切换。深浅色主题跟随系统，也可手动指定。

## 为什么是「PC 数据分析」

Android 版是「掏出手机记一笔」；Web 版的使用场景是「坐在电脑前看账」。因此这一版把重心放在分析上：

- **概览页**是一块仪表盘：累计净输赢、胜率、场均、单场极值、累计净额曲线（可悬停读点）、近 10 场柱状图、分时段战绩、连输/连赢、本月热力日历、牌友净额排行、最近场次
- **月历页**按自然月看逐日战况，点某天即可筛出那天的场次
- **牌友页**是可排序的表格（场均 / 我的场均 / 净额，双向排序），带「最苦主 / 福星 / 牌王」三个标签与迷你走势
- **场次页**支持关键词搜索 + 六维筛选（时段 / 年 / 月 / 日 / 牌友 / 输赢）+ 多选批量删除

记一场、改一场、回收站、归档牌友、JSON 备份导入导出、单场 CSV 导出这些记账功能一个都不少——分析是建立在同一份记录之上的。

## 功能

- **记一场**：填每位牌友的最终净额，或切「赢 / 输」；可以只记录部分位置，合计不必为 0
- **结束时间 + 时长**：只填打完的时刻与时长（默认 4 小时），开始时间与「早 / 下午 / 晚场」由此推出
- **结清建议**：账能平的时候给出笔数最少的转账方案
- **场次列表与详情**：按自然月分组、关键词搜索、六维筛选、多选删除
- **回收站**：删除是软删除，30 天内可还原；超过 30 天在下次打开时自动清除
- **牌友管理**：档案、搜索、归档、双向排序、跨场净输赢、净额走势、逐场记录
- **统计看板**：累计净额曲线、分时段战绩、连输/连赢、最佳/最差单日、单场赢最多/输最多
- **牌友标签**：同场满 3 场时自动标出「最苦主」「福星」「牌王」
- **数据管理**：JSON 全量备份导出 / 导入（与 Android 版协议兼容）、单场 CSV 导出、清空本机数据
- **示例数据**：空库时一键生成 60 余场样本，方便先看清分析长什么样

## 技术栈

| 项 | 版本 |
| --- | --- |
| 框架 | Vue 3.5（`<script setup lang="ts">`） |
| 构建 | Vite 6 |
| 状态 | Pinia 2 |
| 路由 | Vue Router 4（hash 模式，静态托管即可） |
| 样式 | 原生 CSS + CSS 变量（无 UI 框架） |
| 图表 | 手写 SVG 组件（无图表库） |
| 测试 | Vitest 2 |
| 类型 | TypeScript 5.7，`strict` |

图表全部是手写 SVG：`TrendChart`（曲线 + 悬停读数）、`BarChart`（正负柱）、`DonutChart`、`MonthHeatmap`（热力月历）、`SlotBars`（分时段双向条）、`Sparkline`。不引图表库，是为了让配色、刻度和「输赢同时用文字表达」这些口径完全跟着设计令牌走。

## 开发

```bash
pnpm install
pnpm dev          # 开发服务器
pnpm typecheck    # vue-tsc 类型检查
pnpm test         # Vitest 单元测试
pnpm build        # 类型检查 + 生产构建（产物在 dist/）
pnpm preview      # 预览构建产物（本地静态服务器，默认 http://127.0.0.1:5199）
```

想先看看有数据时的样子，打开 `http://127.0.0.1:5199/?demo=1#/`：
只在库为空时铺一份 60 余场的示例数据，不会覆盖任何真实记录。
也可以随时在「我的 → 演示」或空库首页手动载入。

> 本仓库的 `pnpm-workspace.yaml` 里写了 `nodeLinker: hoisted`：Windows 上的沙箱环境对 pnpm 的联接（junction）不友好，扁平安装更稳。同时它声明了 `onlyBuiltDependencies`，允许 `esbuild` 跑自己的安装脚本。

## 从 Android 版继承的口径

这些是原版的「设计取舍」，Web 版逐条实现，不因为换了平台就改口径：

- **金额一律用整数「分」**，全程不经过浮点；`parseAmount` / `divideRounded` 都手工做整数运算
- **人员用 UUID 关联，不按昵称**；保存时写入昵称快照，改名不影响历史
- **统计实时从记录算出**，不另存任何手工累计的账本
- **合计不为 0 只提示、不阻拦**；不平账时不给结清建议——那个建议会建立在错误的总和上
- **未记录的位置不写 0**（导出 CSV 时留空），避免凭空造出一个「持平」
- **时段的判定依据是这一场的中点**：14:00 打到 18:30（中点 16:15）算下午场，17:30 打到 21:30（中点 19:30）算晚场，通宵到早上 6:00 也算晚场
- **删除是软删除**，回收站 30 天；回收站里的场次不参与任何统计，也不写进备份
- **牌友三个标签都落在「同场满 3 场时的场均」上**，且都比场均而不是总账；并列时取 ID 较小者，标签不会在两次刷新之间跳来跳去
- **按数值排序时，没有可谈数字的人始终排在最后**——不是「0 元」，而是根本没有这个数

## 与 Android 版的差异

| 方面 | Android 版 | Web 版 |
| --- | --- | --- |
| 布局 | 手机单列、底部导航 | PC 侧栏 + 多列网格，900px 以下回落单列 |
| 数据 | Room（SQLite） | 浏览器 `localStorage`（单键 JSON 快照） |
| 一致性 | Room 事务 | 先算好新状态再整体落盘，写失败保留旧状态并在界面提示 |
| 分析 | 首页概览 + 月历 | 仪表盘化：曲线、柱状、环图、热力月历、排行并列 |
| 图表 | Compose Canvas | 手写 SVG（可悬停读数） |
| 并发 | 乐观锁 revision | 同样实现 revision，多标签页同时改会拒绝过期提交 |

备份协议版本仍是 **3**，字段与 Android 版一致，因此两边导出的 JSON 可以互相导入。

### 一个必须留意的兼容细节：`durationMinutes` 可能整项缺失

Android 版用 kotlinx.serialization，而它默认 **不输出「等于默认值」的字段**（`encodeDefaults = false`）。
`BackupSession.durationMinutes` 的默认值是 4 小时，于是**时长正好是 4 小时的场次，导出文件里根本没有这个字段**——
而 4 小时正是绝大多数场次的取值。

Android 端读回时会自动补上默认值，所以它自己不觉得有问题；Web 端必须做同样的事：
`decodeBackup()` 把缺失的 `durationMinutes` 补成 240 分钟，而不是判成「不合法的场次时长」。
字段存在但取值非法（例如 250 分钟、20 小时）仍然照旧拒绝——补默认值只是还原协议语义，不是猜测性修补。

`src/domain/backup.spec.ts` 里有一组用例专门锁住这个形状：缺字段能导入、显式时长被保留、
非法时长仍被拒、带 BOM 的文件也能读。

## 验证情况

- `pnpm typecheck`：`vue-tsc` 项目引用模式，0 错误
- `pnpm test`：**87 条断言全绿**，分两类
  - 领域逻辑 74 条：金额/时长解析、排名、结清、统计与取整、连赢连输、单日极值、月度汇总、筛选、备份编解码与拒绝原因、store 的建/改/删/还原/导入/落盘失败回滚
  - 页面渲染 13 条（jsdom + `@vue/test-utils`）：九个页面各自真挂载一次，断言关键文案、表格行数与 SVG 图表；空库态、中英切换与整体外壳（侧栏 + 首屏）各一条
- `pnpm build`：产出 `dist/`，资源用相对路径，可放在任意静态目录

> 当前这台机器的沙箱禁止浏览器进程启动（`msedge/chrome --version` 都拿不到输出），
> 因此**没有做过真实浏览器的视觉走查**：布局与配色只经过代码审查与 DOM 层渲染验证。
> 和 Android 版 README 里那句「尚未在真机或模拟器上运行过」是同一类诚实声明。
> 你本地跑一遍 `pnpm preview` 是最快的确认方式。

## 已知限制

- 数据只存在当前浏览器。换设备、换浏览器、清理站点数据都会丢——请先导出备份。
- 多标签页同时打开时没有跨页实时同步：后写的那个标签页会用它的状态覆盖，另一页刷新后才是最新。
- 没有实现移动端的「桌面快捷方式」与系统级分享，这是平台能力差异。
